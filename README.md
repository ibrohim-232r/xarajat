# Mafia Online

Браузерная «Мафия» для друзей: **React (Vite) + Node.js (Express + Socket.IO)**, устанавливается как **PWA**.
Без скачивания, работает с телефона и компьютера.

## Что внутри

- Главная, список комнат с фильтрами, создание комнаты (режим, число игроков, приватность, пароль)
- Лобби: код комнаты, приглашение по ссылке/коду, добавление ботов, исключение игроков
- Игра: ночь → обсуждение → голосование, чат (ночью — только чат мафии), таймеры, журнал проверок комиссара
- Роли: Мафия, Комиссар, Мирный житель, Доктор (режим «Ночная мафия»)
- Режимы: Классическая (6–12), Быстрая (5–8), Ночная (6–12, с доктором), С друзьями (приватная)
- Боты (заполняют комнату, играют за отключившихся), быстрая игра «в один клик»
- Профиль (уровень, XP, победы/поражения/серия, достижения), магазин (скины, билеты ролей, эмоции, бонусы), монеты
- PWA: manifest, service worker, иконки, установка на главный экран, оболочка работает офлайн

## Запуск

Нужен Node.js 18+.

```bash
npm run setup      # ставит зависимости сервера и клиента
npm run build      # собирает клиент в client/dist
npm start          # сервер + клиент на http://localhost:3001
```

Откройте http://localhost:3001 — в двух вкладках (или с телефона по IP компьютера) можно играть друг с другом.

### Режим разработки (горячая перезагрузка)

В двух терминалах:

```bash
npm run dev:server   # сервер на :3001
npm run dev:client   # Vite на :5173 (проксирует сокеты на :3001)
```

### Docker

```bash
docker build -t mafia-online .
docker run -p 3001:3001 -v mafia-data:/data mafia-online
```

## Структура

```
server/
  src/index.js      Express + Socket.IO: комнаты, события, раздача клиента
  src/game.js       Логика партии: роли, фазы, таймеры, победа, боты
  src/store.js      Профили, магазин, награды (JSON-файл server/data/users.json)
  src/selftest.js   Самотест: 160 партий ботов + проверки приватности и магазина (npm test)
client/
  src/store.jsx     Сокет, состояние приложения, API-обёртки
  src/pages/        Home, Rooms, CreateRoom, Room (лобби+игра), Shop, Profile, Friends, Settings
  public/           manifest.webmanifest, sw.js, иконки
```

## Как устроено

- **Сервер авторитетный**: роли и ходы хранятся только на сервере; клиент получает «отфильтрованное» состояние
  (чужие роли не видны, мафия видит только своих).
- **Профиль** привязан к токену в `localStorage` (гостевой вход, регистрация не нужна).
- Если игрок отключился посреди партии, за него играет автопилот; при возврате он продолжает с того же места.
- Награды: победа +50 монет / +30 XP, поражение +15 / +10. Уровень = каждые 300 XP.

## Настройка

| Переменная      | По умолчанию          | Назначение                                      |
|-----------------|-----------------------|-------------------------------------------------|
| `PORT`          | `3001`                | порт сервера                                    |
| `DATABASE_URL`  | (нет)                 | Postgres/Neon. Если задан — профили хранятся в БД (таблица `users` создаётся сама) |
| `DATA_FILE`     | `server/data/users.json` | JSON-файл профилей, если `DATABASE_URL` не задан |
| `VITE_SERVER_URL` | (тот же origin)     | адрес сервера, если клиент хостится отдельно    |

## Что стоит доделать для продакшена

- Добавить настоящую авторизацию (Google/Telegram). Профили уже хранятся в Postgres, если задан `DATABASE_URL`.
- Ограничить частоту событий (rate limit) и добавить жалобы/бан.
- HTTPS обязателен для установки PWA (кроме localhost).
- Друзья-список и push-уведомления пока не реализованы: приглашение идёт по коду/ссылке.

## Деплой: Neon + Vercel + сервер

Сервер держит комнаты, таймеры и WebSocket-соединения **в памяти**, поэтому он **не может работать на Vercel**
(serverless-функции живут секунды). Схема:

1. **Neon** — база профилей. Таблица `users` создаётся сервером автоматически при первом запуске.
2. **Сервер** (Node, постоянный процесс) — Render / Railway / Fly.io. Подойдёт готовый `Dockerfile`
   или команды `npm run setup && npm start`. В переменных окружения хоста задайте `DATABASE_URL`
   (строка из Neon, лучше с `-pooler`). Запускайте **один экземпляр** (комнаты лежат в памяти).
3. **Vercel** — только клиент: Root Directory = `client`, Framework = Vite, переменная
   `VITE_SERVER_URL` = публичный адрес сервера (https://...). После изменения переменной нужен Redeploy.

Пароль БД нигде не хранится в коде: только в переменных окружения.
